# Telling the work stages apart

How the tracker distinguishes **library management**, **footprint
management**, **schematic work** and **PCB work** - the question the whole
project turns on.

Sources are from a research pass on 24 Oct 2026, labelled as that pass
labelled them: CONFIRMED (vendor docs or source read), LIKELY (secondary or
third-party code), UNKNOWN (needs a local test).

## The problem

**CONFIRMED.** Altium's "Show full path in title bar" option
([docs, AD 15.1](https://www.altium.com/documentation/altium-designer/workspacemanager-dlg-sysprefsform-viewsystem-view-ad?version=15.1))
was **removed in Altium Designer 18.1**
([release notes](https://www.altium.com/documentation/altium-designer/nfs-18-0a-fresh-user-interface-ad?version=18.1)).
Since then the caption leads with the project file. No setting restores it.

Measured in the 22-23 Oct baseline: 8.3 h of about 8.6 h of Altium time
carried only `ESC_Board_5Vbuck.PrjPcb - Altium Designer Professional (26.7.1)`.

**So the title is a dead end, and no amount of regex fixes it.**

## The signal that works: the active document tab (probe-confirmed)

**CONFIRMED on this machine, 24 Oct 2026** (`docs/probe-2026-10-24.md`).
Altium's child windows expose the active document even though the caption does
not. `EnumChildWindows` + `GetClassNameW` + `GetWindowTextW` +
`IsWindowVisible` on the `TDocumentForm`:

| Child class | Caption observed | Meaning |
| --- | --- | --- |
| `TdxTabSheet` | `Home Page` | no document open |
| `TdxTabSheet` | `[1] ESC_PCB.SchDoc` | schematic active |
| `TdxTabSheet` | `ESC_Board.PcbDoc` | PCB active |
| `TViewComponent` | mirrors the tab caption | confirmation |
| `TSCHView_GraphicalForm` (visible) | - | schematic editor on screen |
| `TPCBView_GraphicalForm` (visible) | - | PCB editor on screen |
| `TSCHView_LibraryGraphicalForm` (visible) | - | symbol library editor |
| `TGUIDocBarButton` | `ESC_PCBLIB.PcbLib` | **another** open doc - ignore |

The `[n]` prefix is the sheet number and is stripped. A trailing `*` means
unsaved changes. The extension gives the type, so all four stages separate
with one cheap Win32 pass per tick, and **viewing counts, not just editing**.

Implemented in `pcbtrack/altium.py`; `pick_active()` is tested against the
recorded probe samples in that module's doctests and in `tests/replay_day.py`.

Still unverified: the class name for the **footprint** library editor. Two
candidates are in `EDITOR_CLASSES` (`TPCBView_LibraryGraphicalForm`,
`TPCBLibView_GraphicalForm`). The tab caption already handles `.PcbLib`, so
this only matters as a cross-check - confirm it on the next probe.

## The corroborating signal: Altium's own Auto Save

**CONFIRMED** ([Data Management preferences](https://www.altium.com/documentation/altium-designer/preferences/data-management),
[Project Auto-save & Local History](https://doc-test.altium.com/documentation/altium-designer/project-auto-save-local-history)):
Auto Save "saves a copy of every open document that has been modified but not
saved", naming it `MySchematic.~(1).SchDoc`, into
`%APPDATA%\Altium\Altium Designer <GUID>\Recovery`. A new file appears only
when the document changed since the last Auto Save. Interval and version count
are configurable; Altium's own KB test procedure uses a 1-minute interval.

The **extension is the answer**:

| File written | Document type | Stage |
| --- | --- | --- |
| `*.~(n).SchDoc` | SCH | `schematic` |
| `*.~(n).PcbDoc` | PCB | `routing` (PCB work) |
| `*.~(n).SchLib` | SCHLIB | `library_symbol` |
| `*.~(n).PcbLib` | PCBLIB | `library_footprint` |

**Precedent.** `hackclub/kicad-wakatime` started on KiCad's API and switched
to "look[ing] at the backups generated by KiCAD to detect changes between
saves". Same problem, same solution.
([releases](https://github.com/hackclub/kicad-wakatime/releases))

**Consequence:** since the probe, Auto Save is no longer required for stage
detection - the active document tab covers that. Keep it on anyway: it proves
*editing* (as opposed to viewing) happened, it corroborates the document, and
it is a genuine crash safety net. See `07-install-windows.md`.

**Limit:** Auto Save proves *modification*, not attention. Reading a schematic
without touching it writes nothing, so review-only time falls to the review
queue or a manual note.

## Second signal: Local History and file saves

**CONFIRMED.** On every manual save Altium copies the previous version into a
`History` folder inside the project folder as a zip named like
`SheetZ.~(3).SchDoc.Zip`. With "Add autosaved documents to history" on,
autosaves go there too with a timestamp in the name.
Watching the working files' own mtimes gives the same signal more cheaply.

## Third signal: dialog captions

Altium's modal dialogs *do* name themselves, and in the baseline they
accounted for about 1.2 h that the old tracker filed as "Other". A dialog in
the foreground is the most specific signal available, so it outranks file
evidence from minutes earlier: if the Design Rule Checker is open, that is DRC.

Dictionary in `pcbtrack/rules_default.py`, each entry marked:

- `OBSERVED` - seen in the 22-23 Oct baseline: Polygon Pour Manager,
  Design Rule Checker, Engineering Change Order, Bill of Materials for
  Project, `Replace <part>`, Update From Library, PCB Model, Confirm
  Designator Changes, Smart PDF, Measure Distance, Align Objects.
- `UNVERIFIED` - standard Altium dialogs not yet seen here: Footprint Wizard,
  IPC Compliant Footprint Wizard, Symbol Wizard, Component Editor, Layer Stack
  Manager, Rules and Constraints, Gerber/NC Drill/Pick and Place setup,
  Annotate.

`PCB Model` is worth singling out: it is the dialog that attaches a footprint
to a symbol, which is exactly "matching a footprint when choosing an
alternative component".

## What was ruled out

| Idea | Verdict |
| --- | --- |
| A title-bar setting that shows the document | **CONFIRMED dead.** Removed in AD 18.1. |
| `GetMenu` to read Altium's menus (a `Route` menu would mean PCB editor) | **LIKELY dead.** "GetMenu returns 0 on Altium's DevExpress bars." The menu is not a Win32 HMENU. |
| Child window classes differing per editor | **UNKNOWN.** Main window is `TDocumentForm`; the canvas class looks generic. Some dialogs do have distinct classes. `probe` tests this. |
| UI Automation reading the document tab | **LIKELY possible, partial.** Altium's UIA tree is reported usable for menus, panels and dialogs. Must use `IUIAutomation2` with ~250 ms timeouts: a property read against a hung app was measured at 23 s without them. Deferred to v0.2. |
| A DelphiScript inside Altium | **CONFIRMED most accurate.** `GetWorkspace.DM_FocusedDocument.DM_DocumentKind` returns `'SCH'`/`'PCB'`/`'SCHLIB'`/`'PCBLIB'`. Rejected for v0.1: it must be started inside Altium every session, which breaks "no plugin, no setup". Candidate for v0.3 as an opt-in. |
| Altium 365 history | Too coarse; commits, not activity. |

## Discrimination summary

| Stage | Primary | Secondary | Fallback |
| --- | --- | --- | --- |
| Schematic | active tab `*.SchDoc` | Auto Save `.SchDoc`; visible `TSCHView_GraphicalForm`; Annotate dialogs | review |
| PCB work | active tab `*.PcbDoc` | Auto Save `.PcbDoc`; visible `TPCBView_GraphicalForm`; DRC / Polygon Pour / Layer Stack dialogs | review |
| Library - symbol | active tab `*.SchLib` | Auto Save `.SchLib`; visible `TSCHView_LibraryGraphicalForm`; Update From Library | review |
| Library - footprint | active tab `*.PcbLib` | Auto Save `.PcbLib`; `PCB Model`, Footprint/IPC wizard dialogs | review |
| Component search | LCSC / EasyEDA / DigiKey / Mouser / Octopart in title | `Replace <part>` dialog | review |
| BOM | Bill of Materials dialog; Excel BOM file | | review |
| Client meeting | Zoom / Teams / Meet in title | | `log` by hand |

## Ladder order as built

1. a confirmed / manual label
2. a learned correction rule
3. an **Altium dialog** in the foreground - it says what you are doing *to* the
   document, so it outranks the document itself (DRC over a `.PcbDoc` is DRC)
4. the **active document** from the child windows (confidence 0.92)
5. a document extension in the window caption
6. Auto Save / History file evidence
7. app and domain rules (LCSC, PDF, Zoom, Excel)
8. sticky carry-over
9. `unknown` -> review queue

## Live ordering problem, and the fix

Live the order is: you work five minutes, *then* Altium autosaves. So the
first segments of a session are labelled before any evidence exists.
`classify.backfill` fills them in afterwards from the first high-confidence
neighbour in the same session, capped to the sticky window, and only for
`auto` labels below 0.5 confidence. A human label is never touched.
