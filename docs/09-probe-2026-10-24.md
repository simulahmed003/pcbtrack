# Probe result, 24 October 2026

Raw capture kept local (gitignored - it is 2300 lines of real window titles,
including client project names). Machine: Altium Designer Professional
26.7.1, Windows, process `X2.EXE`. Twelve samples at 10 s while switching
documents.

## What it settled

**The active document is readable from plain Win32.** This was the open
question the whole design hinged on, and the answer is better than the
Auto Save workaround it replaces.

Two top-level `X2.EXE` windows exist:

| hwnd | class | caption |
| --- | --- | --- |
| 984350 | `TApplication` | empty - the hidden VCL window, skip it |
| 132966 | `TDocumentForm` | the real main window |

Under `TDocumentForm`, the `TdxTabSheet` caption tracked the active document
exactly as documents were switched:

| Sample time | `TdxTabSheet` caption | `TViewComponent` | Main window caption |
| --- | --- | --- | --- |
| 17:36:02 - 17:36:32 | `Home Page` | `Home Page` | `ESC_Board_5Vbuck.PrjPcb - ...` |
| 17:36:42 | `[1] ESC_PCB.SchDoc` | same | `ESC_Board_5Vbuck.PrjPcb - ...` |
| 17:36:52 | `ESC_Board.PcbDoc` | same | `ESC_Board.PcbDoc - ...` |
| 17:37:02 onward | `ESC_Board.PcbDoc` | same | `ESC_Board_5Vbuck.PrjPcb - ...` |

Three further findings:

1. **The caption sometimes does show the document** (17:36:52). That explains
   the ~20% of baseline samples that were not the project name. It is not
   dependable, so the tab caption is used instead.
2. **Editor forms exist per open document**, and only the active one is
   visible: `TSCHView_GraphicalForm`, `TPCBView_GraphicalForm`,
   `TSCHView_LibraryGraphicalForm`. An independent confirmation of the type.
3. **`TGUIDocBarButton` must be ignored.** It read `ESC_PCBLIB.PcbLib`
   throughout, including while a schematic was active - it lists *other* open
   documents, not the active one. Reading it would have mislabelled hours of
   PCB work as footprint work.

The canvas class `View_Graphical` is generic across editors, as suspected, and
`TMainWizardForm`, `TModelEditorFrame`, `TXPSplitButton "&Add Footprint"` are
decorative panels that happen to be realised - not evidence of activity.

## Recovery folder

```
C:\Users\<you>\AppData\Roaming\Altium\Altium Designer {D7C2F043-4F91-43CF-8943-507ECBCAFB3C}\Recovery
```

Found by glob, so the GUID needs no configuration. It listed no files during
the probe, which is expected: Auto Save writes only for documents **modified
since the last autosave**, and the probe only switched between documents.
Confirm the `<doc>.~(n).<ext>` naming once real editing has happened.

## Still open

The window class for the **footprint library** editor was never observed,
because no `.PcbLib` was focused during the probe. `altium.py` carries two
guesses (`TPCBView_LibraryGraphicalForm`, `TPCBLibView_GraphicalForm`). This
is only a cross-check - the `.PcbLib` tab caption already identifies it - but
worth confirming on the next probe: open a footprint library and re-run.
